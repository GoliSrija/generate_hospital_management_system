### Database
Database Name:
HospitalManagementSystem

Database Type:
- PostgreSQL

Main Tables:
- Patient
- Staff
- Appointment
- MedicalRecord
- Department

Table Details:

Patient Table:
- PatientID: SERIAL PRIMARY KEY
- FirstName: VARCHAR(50)
- LastName: VARCHAR(50)
- DateOfBirth: DATE
- Gender: CHAR(1)
- PhoneNumber: VARCHAR(15)
- Email: VARCHAR(100)
- Address: TEXT

Staff Table:
- StaffID: SERIAL PRIMARY KEY
- FirstName: VARCHAR(50)
- LastName: VARCHAR(50)
- Position: VARCHAR(50)
- PhoneNumber: VARCHAR(15)
- Email: VARCHAR(100)
- HireDate: DATE

Appointment Table:
- AppointmentID: SERIAL PRIMARY KEY
- PatientID: INTEGER REFERENCES Patient(PatientID)
- StaffID: INTEGER REFERENCES Staff(StaffID)
- DepartmentID: INTEGER REFERENCES Department(DepartmentID)
- AppointmentDate: DATE
- AppointmentTime: TIME
- Status: VARCHAR(20)

MedicalRecord Table:
- RecordID: SERIAL PRIMARY KEY
- PatientID: INTEGER REFERENCES Patient(PatientID)
- StaffID: INTEGER REFERENCES Staff(StaffID)
- Diagnosis: TEXT
- TreatmentPlan: TEXT
- Notes: TEXT
- RecordDate: DATE

Department Table:
- DepartmentID: SERIAL PRIMARY KEY
- DepartmentName: VARCHAR(50)
- Description: TEXT

Primary Key:
- PatientID (Patient)
- StaffID (Staff)
- AppointmentID (Appointment)
- RecordID (MedicalRecord)
- DepartmentID (Department)

Foreign Keys:
- PatientID in Appointment references Patient(PatientID)
- StaffID in Appointment references Staff(StaffID)
- DepartmentID in Appointment references Department(DepartmentID)
- PatientID in MedicalRecord references Patient(PatientID)
- StaffID in MedicalRecord references Staff(StaffID)

Relationships:
- One-to-Many between Patient and Appointment
- One-to-Many between Staff and Appointment
- One-to-Many between Department and Appointment
- One-to-Many between Patient and MedicalRecord
- One-to-Many between Staff and MedicalRecord

Indexes:
- Index on PatientID in Appointment
- Index on StaffID in Appointment
- Index on DepartmentID in Appointment
- Index on PatientID in MedicalRecord
- Index on StaffID in MedicalRecord

Constraints:
- NOT NULL

## Running the frontend locally

Open `frontend/index.html` in a browser or run a static server from
the `frontend` directory:

```bash
python -m http.server 8000
```

Then visit http://localhost:8000.

Note: generated CRUD screens use browser localStorage as a demo.
They are not connected to a real database unless backend integration
is implemented separately.
